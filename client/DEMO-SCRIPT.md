# Kanbot — دليل المشروع وسكريبت العرض

هذا الملف يشرح فكرة Kanbot وبنيته وكيفية تشغيله واستخدامه، ثم يعطي مسارًا جاهزًا لعرض أهم الميزات. أسماء المكتبات والمسارات البرمجية تبقى كما هي في الكود لتسهيل البحث عنها.

## 1. ما هو Kanbot؟

Kanbot تطبيق لإدارة المشاريع والمهام بطريقة Kanban وScrum. المستخدم ينشئ مشاريع، يضيف المهام إلى قائمة Backlog، يخطط Sprint من المهام، يتابع تنفيذها على Board، ثم يكمل Sprint ويراجع إحصاءاته وملخصه. يوجد مساعد AI للمحادثة، وتوليد مسودات المهام، واقتراح خطة Sprint، وتلخيص Sprint.

التطبيق يدعم العربية والإنجليزية، واتجاه RTL للعربية، ووضعي الألوان النهاري والليلي. الوضع الليلي هو الافتراضي. بيانات المشروع والمهام والسبرنتات محفوظة في API، بينما تفضيلات اللغة والمظهر وسجل محادثات AI محفوظة محليًا في المتصفح.

## 2. كيف تتصل أجزاء النظام؟

المشروع مقسوم إلى تطبيق واجهة client/ وخادم API في server/:

1. المتصفح يعرض واجهة React ويطلب البيانات من API.
2. الواجهة ترسل طلبات HTTP عبر عميل مشترك، وتضع رمز الجلسة JWT مع الطلبات المحمية.
3. الخادم يتحقق من الطلب والرمز وملكية المستخدم للبيانات، ثم ينفذ منطق المشروع أو المهمة أو Sprint.
4. الخادم يحفظ بيانات التطوير في ملف JSON ويرسل استجابة JSON للواجهة.
5. TanStack Query يحتفظ بنسخة مؤقتة من بيانات الخادم ويحدّث الشاشة بعد القراءة أو التعديل.

    المتصفح
      └─ React + React Router + TanStack Query
           └─ طلبات HTTP إلى /api
                └─ Express + تحقق JWT و Zod
                     └─ خدمات المشروع والمهام و AI
                          └─ JSON database محلية أو مزوّد AI

الخادم هو مصدر الحقيقة لبيانات الحسابات والمشاريع والمهام والسبرنتات. localStorage ليس قاعدة بيانات للمشروع؛ يستخدم لإعدادات المتصفح وسجل محادثات AI المحلي.

## 2.1 كيف يبدأ التطبيق ويتنقل؟

نقطة البداية هي client/src/main.tsx. يحمّل React ثم يجهز Providers العامة: TanStack Query لحالة الخادم، LanguageProvider للغة والاتجاه، ThemeProvider للمظهر، وAuthProvider للجلسة. بعدها يركّب RouterProvider لعرض الصفحة المناسبة.

المسارات العامة هي /login و/register. المسارات الأساسية المحمية هي /projects ثم /projects/:projectId/backlog و/projects/:projectId/board و/projects/:projectId/sprints. AppShell يحيط صفحات العمل ويوفر الشريط الجانبي، عنوان الصفحة، اختيار المشروع، اللغة، المظهر، وزر Ask AI. الصفحات تُحمّل عند الحاجة باستخدام lazy loading وSuspense لتقسيم JavaScript حسب المسار وإظهار حالة تحميل بدل الانتظار بصمت.

## 5. بدء تشغيل التطبيق

من مجلد المشروع الرئيسي افتح طرفيتين.

    cd server
    npm install
    Copy-Item .env.example .env
    npm run dev

يعمل API افتراضيًا على http://localhost:4000/api. أنشئ .env من المثال عند إعداد نسخة جديدة. لا تشارك ملف .env ولا تضع أسرارًا فيه ضمن Git.

    cd client
    npm install
    npm run dev

افتح http://localhost:5173.

## 6. مسار المستخدم من البداية

### أ. إنشاء حساب وتسجيل الدخول

- صفحة التسجيل تتحقق من الحقول، ثم يكرر الخادم التحقق قبل إنشاء الحساب.
- البريد فريد؛ محاولة استخدام بريد موجود ترجع تعارضًا 409 مرتبطًا بحقل البريد.
- كلمة المرور لا تخزّن نصًا صريحًا؛ يخزن الخادم hash مع salt باستخدام scrypt.
- عند نجاح الدخول يصدر الخادم JWT. تستخدم الواجهة الرمز في طلبات API المحمية.
- GuestRoute يسمح بصفحات الدخول والتسجيل للزائر، وProtectedRoute يطلب جلسة صالحة قبل صفحات المشروع. إذا انتهت الجلسة يعود المستخدم للدخول، وبعده يمكن إرجاعه للمسار الذي كان يفتحه.
- تسجيل الخروج ينهي حالة الجلسة في الواجهة. بيانات المشاريع تبقى على الخادم، ومحادثات AI المحلية لا تُحذف تلقائيًا.

### ب. إنشاء مشروع

كل المهام والسبرنتات تتبع مشروعًا محددًا. المشروع يتضمن اسمًا ووصفًا ومفتاحًا قصيرًا مثل KAN. إذا لم يُدخل المستخدم مفتاحًا، ينشئه الخادم من الاسم ويبحث عن مفتاح بديل عند التعارض. إذا أدخل مفتاحًا مستخدمًا، تظهر استجابة 409 على الحقل. كل مهمة جديدة تحصل على مفتاح من نمط KAN-1.

صفحة المشاريع تعرض بطاقات فيها معلومات موجزة وعدد مهام Backlog والسبرنت النشط إن وجد، وتوفر البحث والإنشاء والتعديل والحذف مع تأكيد.

### ج. إدارة المهام في Backlog

Backlog هي قائمة المهام التي لم توضع بعد في Sprint. يمكن للمستخدم:

- إنشاء مهمة بسرعة، أو فتح تفاصيلها لتعديل العنوان والوصف والنوع والأولوية والنقاط والمسؤول والحالة.
- حذفها بعد التأكيد.
- البحث بالعنوان أو المفتاح أو المسؤول أو الوصف/التسميات، وتصفية المهام حسب الأولوية والنوع.
- إعادة ترتيب المهام أو نقلها إلى Backlog أو Sprint مخطط.
- مراجعة إجمالي عدد المهام والنقاط.

البحث مؤجل قليلًا (debounce) حتى لا يرسل طلبًا مع كل حرف. عند النقل يستخدم التطبيق تحديثًا متفائلًا: يغير الواجهة أولًا ثم يثبت التغيير من الخادم؛ إذا فشل الطلب يعيد الحالة السابقة ويظهر إشعارًا.

### د. تخطيط وبدء Sprint

Sprint هو فترة عمل محددة بهدف وتواريخ ومجموعة مهام. يمكن إنشاؤه يدويًا أو قبول اقتراح AI:

1. اختر مهام Backlog التي ستدخل السبرنت وحدد الاسم والهدف والتواريخ.
2. يمكن اقتراح المهام وفق سعة capacity؛ يجب ألا يتجاوز مجموع نقاطها السعة المطلوبة.
3. السبرنت المخطط يظهر أعلى Backlog وبصفحة Sprints.
4. ابدأه بتأكيد التواريخ. لا يسمح التطبيق بوجود Sprint نشط آخر في المشروع نفسه.
5. عند البدء تظهر المهام على Board.

يمكن تعديل Sprint مخطط أو حذفه. حذف Sprint مخطط يعيد مهامه إلى Backlog. السبرنت النشط لا يحذف بهذه الطريقة؛ يجب إكماله.

### هـ. العمل على Board وإكمال Sprint

Board يعرض مهام Sprint النشط في أعمدة الحالة:

- To Do — لم يبدأ العمل.
- In Progress — قيد التنفيذ.
- In Review — بانتظار المراجعة.
- Done — اكتمل.

اسحب البطاقة بين الأعمدة أو غيّر حالتها من عناصر التحكم المتاحة. تتحدث أعداد المهام والتقدم والنقاط المكتملة وفق الحالة. يمكن فتح البطاقة لتعديل تفاصيلها. عند عرض شاشة أصغر، يمكن تمرير الأعمدة أفقيًا.

عند إكمال Sprint، تظهر نافذة تتيح نقل المهام غير المكتملة إلى Backlog أو Sprint مخطط. يحفظ الخادم إحصاءات الإكمال وحالة المهام التي لم تنتهِ، ثم يصبح Sprint ضمن السجل. تفاصيل السبرنت المكتمل تعرض الإحصاءات والملخص المحفوظ وإمكانية إعادة توليده.

### و. مساعد AI

للمساعد ثلاث أدوات رئيسية إضافة إلى المحادثة:

- **Create todos:** وصف ما تريد بناءه، مراجعة المسودات وتعديلها وإلغاء تحديد غير المناسب منها، ثم حفظ المختار دفعة واحدة في Backlog.
- **Plan sprint:** تحديد السعة والتركيز، مراجعة الهدف والمهام المقترحة، ثم إنشاء Sprint بالاختيار.
- **Summarize sprint:** توليد ملخص من هدف السبرنت وحالات المهام، حفظه مع تاريخ الإنشاء، ثم إعادة توليده عند الحاجة.

المحادثة والملخصات تعرض Markdown عبر react-markdown. سجل المحادثات محفوظ محليًا في المتصفح ومفصول بحسب المستخدم والمشروع؛ لا يتزامن بين الأجهزة ولا يعتبر جزءًا من ملف قاعدة JSON. حالات التحميل والخطأ وزر إعادة المحاولة تظهر عندما يتعذر طلب AI.

#### وضع المحاكاة والمزود الحقيقي

- دون AI_API_KEY يعمل الخادم بوضع Mock AI. هذا الوضع مفيد للتجربة ولا يحتاج إنترنت أو مفتاح مزود.
- لمعرفة الوضع استدعِ GET /api/ai/status؛ يرجع وضع mock أو ai واسم النموذج عند تفعيل المزود.
- لاستخدام Groq أو مزود متوافق مع OpenAI، اضبط في server/.env:
  - AI_API_KEY — المفتاح السري.
  - AI_BASE_URL — عنوان API للمزود.
  - AI_MODEL — اسم نموذج متاح لحساب المزود.
- أعد تشغيل الخادم بعد تعديل البيئة. لا تضع المفتاح في client/.env أو متغير VITE_* أو في تسجيل الشاشة.
- الخادم يتحقق من مخرجات AI قبل استخدامها، ويطبق حدًا لطلبات AI. إذا كانت الاستجابة غير صالحة لبعض عمليات التوليد/التخطيط يمكن استخدام نتيجة Mock كبديل.

## 7. مسارات API المهمة

كل المسارات التالية تحت /api. معظمها يتطلب JWT؛ استثناء مسارات التسجيل والدخول والصحة. التفاصيل الكاملة والأنواع موجودة في server/src/routes/ وserver/src/types/api.ts.

| المسار | وظيفته |
| --- | --- |
| GET /health | فحص أن الخادم يعمل. |
| POST /auth/register و POST /auth/login | إنشاء حساب أو بدء جلسة. |
| GET /auth/me | إعادة المستخدم الحالي للجلسة. |
| GET/POST /projects | عرض مشاريع المستخدم أو إنشاء مشروع. |
| GET/PATCH/DELETE /projects/:projectId | قراءة مشروع أو تعديله أو حذفه. |
| GET/POST /projects/:projectId/todos | قراءة مهام المشروع وإنشاء مهمة. يدعم GET بحثًا وفلاتر وsprintId=backlog. |
| POST /projects/:projectId/todos/bulk | حفظ مسودات مهام مختارة دفعة واحدة. |
| GET/PATCH/DELETE /todos/:todoId | قراءة مهمة أو تعديلها أو حذفها. |
| POST /todos/:todoId/move | نقل مهمة أو تغيير ترتيبها. |
| GET/POST /projects/:projectId/sprints | قراءة سبرنتات المشروع أو إنشاء Sprint. |
| GET /sprints/:sprintId/todos | بيانات Sprint وأعمدة Board مجمعة حسب الحالة. |
| POST /sprints/:sprintId/start و POST /sprints/:sprintId/complete | بدء Sprint أو إكماله ونقل غير المنتهي. |
| GET /ai/status | معرفة وضع AI والنموذج الفعال. |

## 8. اللغة والمظهر والتجاوب

- LanguageProvider يدير الإنجليزية والعربية؛ العربية تضبط dir=rtl وترجمة واجهة التطبيق وتنسيق التاريخ/الأرقام.
- أسماء المشاريع والأوصاف والمهام التي يكتبها المستخدم لا تُترجم تلقائيًا.
- ThemeProvider يحفظ اختيار النهاري أو الليلي محليًا، والليلي هو الافتراضي.
- Tailwind utilities وتوكنات client/src/index.css تشكل نظام الألوان والخطوط والمسافات والمكونات. الخط الأساسي Geist، مع IBM Plex Sans Arabic للنص العربي.
- عند عرض أصغر من أو يساوي 768px يتحول التنقل إلى قائمة جانبية قابلة للفتح، ويمكن تمرير Board أفقيًا. عند 1024px تبقى واجهة سطح المكتب وتتحرك الجداول الواسعة داخل مناطقها.

## 9. العرض الحي المقترح (3–5 دقائق)

### قبل التسجيل

1. شغّل الخادم والواجهة حسب قسم التشغيل.
2. استخدم بيانات seed أو حسابًا تجريبيًا جديدًا ومشروعًا جديدًا حتى لا تعدّل بياناتك الشخصية.
3. تأكد أن AI في Mock أو أن المزود الحقيقي مضبوط. لا تُظهر كلمة مرورك أو AI_API_KEY في الفيديو.
4. جهز صفحة المشروع على Backlog.

### نص العرض

1. **ابدأ من المشاريع:** «Kanbot ينظم عدة مشاريع. كل مشروع له مفتاح، وتظهر منه مهامه وسبرنتاته».
2. **افتح Backlog:** أضف مهمة سريعة، ثم افتح مهمة واعرض نوعها وأولويتها ونقاطها والمسؤول عنها. جرّب البحث أو أحد الفلاتر.
3. **اعرض المساعد:** افتح Ask AI واختر Create todos. اكتب وصفًا لميزة، راجع المسودات، عدّل مسودة وألغِ تحديد مسودة ثم احفظ المختار. أشر إلى أن الحفظ دفعة واحدة.
4. **خطط Sprint:** اختر Plan sprint، عيّن سعة مثل 8 واكتب تركيزًا، ثم راجع المهام والهدف المقترحين وأنشئ السبرنت.
5. **ابدأ Sprint:** من قسم السبرنتات المخططة اختر Start sprint. اعرض الهدف والتواريخ ومؤشر التقدم.
6. **تابع Board:** انقل مهمة من To Do إلى In Progress ثم In Review ثم Done. وضح أن عدد المهام والتقدم يتغيران مع الحالة.
7. **أكمل Sprint:** افتح Complete sprint، اختر وجهة المهام غير المكتملة، وأكد الإكمال.
8. **اعرض سجل Sprints:** افتح السبرنت المكتمل، اشرح بطاقات الإحصاءات والملخص، ثم جرّب Regenerate summary.
9. **اختم:** بدّل اللغة أو المظهر لإظهار RTL والوضع النهاري/الليلي، ثم وضح أن إعدادات العرض وسجل المحادثات محلية لهذا المتصفح.

### نص بديل عند عدم وجود مزود AI حقيقي

استخدم نفس الخطوات مع Mock AI. اذكر للمشاهد أن التطبيق يعمل بوضع المحاكاة، ثم اعرض شارة/حالة AI. لا تدّع أن الإجابة في هذا العرض جاءت من نموذج حقيقي.

## 10. ما أُنجز وما له حدود

الموجود في المشروع: تسجيل ودخول وحماية مسارات، إدارة مشاريع، مهام Backlog وبحث وفلاتر ونقل وترتيب، دورة Sprint من التخطيط حتى السجل، Board بأعمدة الحالة، مساعد AI بخيارات المحاكاة والمزود الحقيقي، المحادثات والملخصات، العربية/الإنجليزية، RTL، مظهر ليلي/نهاري، حالات تحميل وفراغ وخطأ، وإشعارات.

حدود النسخة الحالية:

- قاعدة JSON المحلية مناسبة للتطوير والتجربة على خادم واحد؛ ليست قاعدة بيانات إنتاجية متعددة النسخ.
- سجل المحادثات وتفضيلات اللغة والمظهر في localStorage لهذا المتصفح فقط؛ لا يوجد تزامن بين الأجهزة.
- لا يوجد وضع Offline.
- لا توجد حاليًا مجموعة اختبارات واجهة Unit أو Playwright E2E ضمن Client scripts. يوجد فحص API باسم server/npm run smoke.
- مراجعة التباين مبنية على ألوان النظام، وليست شهادة WCAG لكل حالة مرئية أو لكل عنصر أصلي من المتصفح.
- الفيديو نفسه غير مرفق بهذا الملف؛ هذا الملف يحتوي خطوات ونص العرض لتسجيله.

للتفاصيل التشغيلية المختصرة راجع client/README.md، ولخريطة المكتبات حسب Feature راجع client/src/features/README.md. ولتفاصيل API المرجعية راجع docs/IMPLEMENTATION-PLAN.en.md القسم 4.
